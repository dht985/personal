# 职业情报周报（Career Weekly）

面向云南大学计算机专业本科生的**能源/军工类央国企职业情报周报**。

它不是新闻聚合器，而是**信息收拢器**：

- 每周巡检 4 个缺源单位，并抓取全部已启用公开信源
- 用本地 `qwen3:8b` **只判断"这条收不收"**，不做解读、不改写标题
- 输出：原标题 + 原文链接 + 日期 + 层级 + 一句筛选理由
- 判断留给你自己

## 它回答什么

- 这周这些单位在招什么人、在做什么方向、有哪些公开动态
- 哪些信息值得你点开看（AI 只做筛选）

**不回答**：你该学什么、该选哪条职业路线。这部分明确交给读者。

## 快速开始

```powershell
pip install -r requirements.txt

# 确认本地模型（CPU 上约 1–2 秒/批）
ollama list          # 应看到 qwen3:8b
ollama serve         # 如未运行

python -m cw run              # 抓取 + AI 筛选 + 生成周报
python -m cw run --no-llm     # 不用 AI，规则命中全收
python -m cw discover-sources --limit 4  # 巡检官网，继续补招聘/政策/新闻源
python -m cw coverage         # 查看招聘、政策等数据覆盖与通道缺口
python -m cw open             # 用默认程序打开最新周报
python -m cw status           # 查看库内条目
python -m cw discover         # 发现 L3 部门/实验室候选
```

输出：`outbox/weekly-latest.md`（同时保留按日期命名的版本）。

## 设计原则

| 原则 | 说明 |
| --- | --- |
| 单位做减法 | 只跟踪能源/军工类央国企（含省属、含院所/子公司） |
| 赛道做加法 | 工业软件、嵌入式、算法、数据平台、安全、产品、测试……全部保留 |
| 三级归属 | L1 集团总部 / L2 院所·子公司 / L3 下属部门·实验室 |
| 来源优先 | 每条必须有原文链接，没有链接的不进周报 |
| AI 只筛选 | 不生成"意义"、不做解读、不改写标题 |
| 失败不丢信息 | AI 调用失败时按"规则命中先收录"处理 |
| 持续补源 | 每周巡检官网导航，记录失败尝试，下一轮继续其他单位 |

## 数据层：A 政策/公开文件 + B 招聘数据

每个信源都有 `purpose`，取值为：

| 用途 | 内容 | 示例栏目 |
| --- | --- | --- |
| `recruit` | 校招、社招、技术岗位、招聘结果 | 人才招聘、招聘公告 |
| `policy` | 政策、规划、办法、制度和信息公开文件 | 信息公开、公示公告 |
| `news` | 新闻、研发、项目、投资和技术动态 | 集团要闻、科技动态 |

周报会单独统计本期招聘条数、政策/公开文件条数，以及启用的三类信源数。
`python -m cw coverage` 会继续显示每个单位缺哪类数据。

### 自主持续发现

系统不再依赖抓取搜索引擎结果页。经实测，搜狗的 `robots.txt` 限制 `/web`
和 `/link`，因此项目只在各单位的公开官网导航中找栏目，不绕过访问限制。

每轮会自动：

1. 找出缺少 `recruit` / `policy` / `news` 通道的重点单位；
2. 优先巡检最久未检查的单位，读取官网公开导航；
3. 验证候选页面的同站域名、内容链接数与目标词；
4. 把成功来源写入 `config/sources_auto.toml`；
5. 把成功、拒绝、无候选、官网失败写入 SQLite 的 `discovery_attempts`；
6. 对失败候选保留 30 天冷却，避免每周重复撞同一页面；
7. 下一周从上次之后继续巡检，不会抓完一次就停止。

当前未配置付费搜索 API。若以后接入合规的搜索 API，只需在发现层增加适配器，
不需要改动抓取、筛选或报告模块。

## 关注范围（CS 相关）

不是所有能源/军工央国企都采，也不按名字字面筛选，只采 **CS 相关性强**的：

- 有专门的软件/计算类院所（如 28所、208所、631所、709所、706所）
- 有数字化/IT 子公司（如 中国软件、麒麟软件、南瑞、国网信通、石化盈科、昆仑数智）
- **软件密集型工程院所**：雷达、控制、导航、仿真、测控、光电——名字不含"计算/软件"，但软件岗位很多（如 14所、601所、618所、航天一院/五院、701所）
- 招聘明确需要软件/算法/数据岗位

清单在 `config/focus.toml`，共 **73 个单位**。不在清单里的单位只登记、不采集。
要增删关注对象，只改这个文件，不动代码。

## 架构

```
config/
  units.toml      单位登记表（三级、类别、地区、层级、官网）
  units_l2.toml   L2 院所补充登记
  focus.toml      CS 相关重点关注名单
  tracks.toml     赛道与交叉标签（开放）
  sources.toml    信源（静态 / 渲染 / 人工维护）
  sources_auto.toml  自动发现并通过验证的信源（运行时生成）
  settings.toml   周报长度、回溯窗口、模型参数
cw/
  net.py          静态抓取（限速、重试、原始快照）
  browser.py      Playwright 渲染（JS 页面 / 反爬站点）
  discover_sources.py  官网通道巡检、用途识别、尝试记录
  parse.py        列表页解析（过滤导航、旧归档、成员企业链接）
  classify.py     信号类型 + 赛道/标签 + 噪声过滤
  llm.py          qwen3:8b 批量收录判断
  manual.py       人工维护源解析
  store.py        SQLite（URL 去重、首次发现、巡检尝试）
  report.py       Markdown 周报（≤4 页、带链接）
  pipeline.py     编排
  cli.py          命令行
manual/
  211.md          211所人工维护源（官网缺失）
tests/
  test_core.py    解析、分类、去重、报告、时效
```

数据流：

```
信源(静态/渲染/人工)
  → 列表解析
  → 规则预过滤（导航/党务/无关岗位/旧归档）
  → AI 批量筛选（收/不收 + 理由）
  → 层级/单位/信号配额
  → Markdown 周报
```

## 单位三级模型

| 层级 | 是什么 | 决定什么 | 示例 |
| --- | --- | --- | --- |
| L1 | 集团总部 | 战略、预算、统一政策 | 中国电科、中国航发、国家管网 |
| L2 | 院所 / 子公司 | **招聘主体**、专业目录 | 54所、211所、南网数字 |
| L3 | 部门 / 实验室 | 具体项目、技术栈 | 云大就业平台（校招汇总） |

周报每条都标注层级，避免把集团战略当成岗位信号。

## 如何扩展

### 新增一个单位

在 `config/units.toml` 追加：

```toml
[[unit]]
id = "example"
name = "某某集团有限公司"
short = "某某"
home = "https://example.com/"
level = 1
category = "能源"
region = "全国"
tier = "watch"
```

### 新增一个信源

静态列表页：

```toml
[[source]]
id = "example-news"
unit = "example"
name = "某某·新闻中心"
url = "https://example.com/news/"
purpose = "news"
```

需要浏览器渲染：

```toml
[[source]]
id = "example-news"
unit = "example"
name = "某某·公司新闻"
url = "https://example.com/news/"
purpose = "news"
render = true
```

没有官网、只能人工维护：

```toml
[[source]]
id = "manual-example"
unit = "example"
kind = "manual"
name = "某某·人工维护"
path = "manual/example.md"
```

人工文件格式：

```markdown
- [标题](链接) | 2026-11-01
```

### 新增一条赛道

在 `config/tracks.toml` 追加 `[[track]]`，给出关键词即可被自动匹配。

## AI 的角色

- 模型：本地 Ollama `qwen3:8b`
- 方式：每批 8 条标题，关闭 thinking（`think: false`），约 1–2 秒/批
- 输出：`{"decisions":[{"i":0,"include":true,"reason":"技术岗位招聘"}]}`
- 约束：只判断收录与否；理由 ≤20 字且不含数字
- 失败：整批回退为"规则命中先收录"，不丢信息

**报告里的标题和链接是原文，AI 只提供筛选理由；理由可能不准确，仅供筛选参考。**

## 已知限制

- **国家电网、中国石油**：官网与招聘门户均返回 412，Playwright 也是空页，暂未接入
- **211 所**：无公开官网，使用 `manual/211.md` 人工维护
- **南网数研院 / 中国海油**：资讯页需要 Playwright 渲染
- **航天科工、中国船舶**：官网可抓，但本周条目多为领导调研/会议稿，未命中信号
- **L3**：公开组织架构少，`discover` 只找到 1 个候选
- **通道缺口**：仍有很多 L2 院所没有可验证公开官网，自动巡检只能覆盖有官网地址的单位
- **AI 理由只用于筛选**：可能把“项目动态”误写成“岗位信息”，事实仍以原链接为准
- 长文本页面会退化为全页文本，正文抽取是通用启发式
- **不要按编号猜院所域名**：实测 `cetc29.com` 是抢注的博彩站，只接人工确认过的官网

## 给其他 AI / 开发者的建议

后续最值得做的三件事：

1. **补齐无官网 L2 的公开入口**：只接人工核验过的域名，不能按编号猜
2. **增加更多官方招聘门户解析器**：部分门户只在浏览器中显示少量导航文本
3. **接入合规搜索 API（可选）**：对官网导航无法覆盖的新页面做补充发现

不要做的事：

- 不要编造日期、岗位、数字
- 不要把 AI 的"收录理由"当成事实
- 不要绕过登录、付费墙或访问限制
- 不要删除人工维护源
